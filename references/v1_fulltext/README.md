# v1.0 full-text retrieval and eligibility (protocol §6–§8)

This directory is the record of the full-text stage: which drawn records were
retrieved and how (§8), the eligibility assessment of each retrieved record
(§4, §6), and the checks on the agents that made those assessments
(Amendment 1, items 3 and 26). The walk itself (§7) is computed from these
files by `scripts/v1_search/fulltext.py status`.

## Files

| File | Content |
|---|---|
| `retrieval_plan.csv` | Every frame record in draw order within its stratum, with its two routes: route 1 (`route1_url`, the OpenAlex `best_oa_location` PDF or landing page, else `open_access.oa_url`) and route 2 (`route2_url`, the DOI). Written by `fulltext.py plan`. |
| `retrieval_log.csv` | One row per route tried for each file (`main.pdf`, `si1.pdf`, ...; `si` when no supplementary file was listed): route, URL, outcome (`obtained`, `no_full_text`, `not_available`), SHA-256 and size of the obtained file, time, and a note saying what happened. Written by `fulltext.py log`. |
| `eligibility.csv` | One row per assessed record: both assessors' decisions and codes, agreement, the resolver's decision when one was needed, and the outcome. Written by `fulltext.py collect`. |
| `eligibility/<frame_id>/` | The assessments themselves (`a.json`, `b.json`, and `resolver.json` when used). |
| `access/` | One check report per eligibility agent from `scripts/v1_search/fulltext_runs.py` (launcher, frozen prompt SHA-256, model, access audit, output format). |
| `access_reviews.json` | Each audit flag that was reviewed by reading the call, with the finding. A flag counts as access unless its review says otherwise. |

`walk.json` is regenerated by `fulltext.py status` and is not committed.

## Retrieval (§8)

- **Route 1** is the plan's `route1_url`. **Route 2** is the DOI opened through
  the University of North Texas library proxy
  (`https://libproxy.library.unt.edu/login?url=https://doi.org/<doi>`), with
  the author signed in to the library. The author entered his own library
  credentials in the browser; the AI that operated the browser never saw or
  handled them.
- **Browser.** Retrieval was carried out by Claude (Anthropic) operating a
  browser on the author's computer. Until the Claude in Chrome extension was set
  up (about 07:08 UTC on 29 Oct 2026) this was the built-in browser of the
  Claude desktop app; from then on it was the author's own Chrome, because
  ScienceDirect, Wiley and IOPscience did not serve full text to the built-in
  browser. Notes from 07:08 UTC on name Chrome where it was used.
- **Saving.** A PDF is fetched inside the page with the page's own session and
  saved unmodified as `hycan_ft_<frame_id>_<file>` by the functions in
  `scripts/v1_search/fulltext_fetch.js`, which check that the bytes start with
  `%PDF-`; supplementary files that the publisher serves as downloads are saved
  by the browser and renamed. The SHA-256 and size in the log are computed on
  the saved file. PDFs are kept outside the repository and are not
  redistributed (§14); the log keeps their SHA-256. Some publishers stamp each
  download (ScienceDirect, Trans Tech, Oxford Academic), so the same article
  gives different bytes on a second download.
- **Order.** Route 1 is tried first when the plan has one. Route 2 is tried only
  when route 1 did not obtain the main text. Supplementary files are taken from
  the route that obtained the main text.
- **Supplementary information.** Document files (PDF, Word, Excel, text) are
  retrieved; files in another document format are converted to PDF for the
  assessors with `soffice` (`fulltext.py stage`), and a supplementary zip is
  unpacked to the one document it holds. The original file and its SHA-256 stay
  in the store and the log. Non-document supplementary files (videos) are not
  retrieved.

### Implementation rules

These rules were fixed before the outcomes they govern and are applied to every
record alike, so that retrieval effort is the same for every record (§8).

1. A page that fails to load is reloaded once.
2. The AI never completes a CAPTCHA. A route-1 page that answers with a CAPTCHA
   is logged `no_full_text` and route 2 is tried.
3. A route that fails only because a bot check (Cloudflare verification, the
   IEEE Xplore challenge) or a server error (HTTP 5xx) blocks the browser is
   tried once more, in a fresh tab, after a pause of at least 30 minutes; the
   outcome of that second attempt is final. The second attempt is part of the
   route's one try, so the route keeps one log row, whose note describes both
   attempts and the time of the second. This
   rule was added at 09:40 UTC on 29 Oct 2026, after Ingenta Connect served one
   record's page through the library proxy and then refused the immediate
   reload, which showed that these blocks can be transient. It applies equally
   to the records already logged `no_full_text` for this reason (F07150,
   F07677, F07809).
4. A route-1 location whose page offers only purchase, or whose `pdf_url` is not
   the article (an abstract page, a graphical-abstract image, a 404), is logged
   `no_full_text` and route 2 is tried.

### Incidents

- **F02340.** A route-2 copy was fetched by mistake before the available route-1
  PDF; it was set aside unused and the route-1 PDF was retrieved and logged.
- **F04959.** The first save took the "View PDF" link of a cited reference
  (ScienceDirect lists them on the article page); the file was set aside unused,
  the article's own PDF was saved and logged, and the link selection was
  restricted to the article's own PII.
- **F01856.** Chrome silently blocked a script-initiated save in a tab that had
  already downloaded a file; the PDF was saved again from a fresh tab, and from
  then on every record uses a fresh tab.

The `stage` step checks every main PDF's first page against the record's title;
every stored main text was confirmed to be the drawn article (one 1980 scan
without a text layer, F07841, was checked by eye).

## Eligibility (§4, §6)

Each retrieved record is assessed by two agents with the frozen prompt
`prompts/v1/built/eligibility.md`: A (claude-opus-5-5) and B
(claude-sonnet-5-5), each with an input directory under a parent of its own
(record.json, the text layer of every PDF, and page images). When they
disagree, a resolver (claude-opus-5-5, `eligibility_resolve.md`) decides with
both assessments in view. Every agent is checked by `fulltext_runs.py`; an agent
whose check fails is rerun only for a technical failure (§9). The author reviews
every full-text exclusion (§6).
